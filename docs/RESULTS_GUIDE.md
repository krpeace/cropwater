## 1. 공통 사항

### 1.1 설정 시트 사용법

모든 엑셀 파일의 첫 번째 시트는 **설정**입니다. 노란색 셀을 수정하면 다른 시트의 값이 자동으로 갱신됩니다.

| 셀 | 항목 | 편집 | 설명 |
|----|------|------|------|
| B4 | **올해** | ✅ | 기준 연도. 바꾸면 올해/작년/평년이 자동 재계산 |
| B5 | 작년 | ❌ | `=B4-1` 자동 계산 |
| B6 | **평년 기간** | ✅ | 기본 10년. 바꾸면 평년 범위 자동 변경 |
| B8 | 분석 시작일 | 📝 | 변경 시 스크립트 재실행 필요 |
| B9 | 분석 종료일 | 📝 | 변경 시 스크립트 재실행 필요 |

> **B4(올해)와 B6(평년 기간)은 즉시 반영됩니다.** B8·B9(분석 기간)는 표시 전용이며, 실제 기간을 바꾸려면 스크립트를 다시 실행해야 합니다.

### 1.2 비교 행 구조

권역별·지점별 시트의 각 지표는 5행으로 구성됩니다.

| 행 | 의미 | 계산 |
|----|------|------|
| 올해(2026) | 기준 연도 값 | VLOOKUP으로 REF에서 조회 |
| 작년(2025) | 직전 연도 값 | 동일 |
| 평년(2016~2025) | 과거 10년 평균 | 동일 |
| 차이(전년) | 올해 − 작년 | 수식 |
| 차이(평년) | 올해 − 평년 | 수식 |

**차이 행 해석:** 양수(+)이면 올해가 작년/평년보다 높고, 음수(−)이면 낮습니다.

### 1.3 권역별 집계 방식

엑셀의 "권역별" 시트 값은 해당 권역에 속한 **ASOS 지점의 단순 산술 평균**입니다. 기상청(KMA) 공식 통계와 방법론이 다르므로 값이 동일하지 않습니다. KMA 공식 값이 필요하면 "지점별" 시트에서 해당 대표 지점을 직접 조회하세요.

### 1.4 동기간 비교

올해 데이터가 9월 15일까지 있으면, 작년·평년도 **1월 1일~9월 15일** 범위만 사용합니다. 올해는 9개월, 평년은 12개월 — 이런 불공정 비교를 자동으로 방지합니다.

### 1.5 콤보 박스(드롭다운)

권역별·지점별 시트 좌상단의 노란 셀에 드롭다운이 있습니다. 권역이나 지점을 선택하면 해당 데이터로 즉시 전환됩니다.

### 1.6 숨긴 시트

이름이 `_`로 시작하는 시트(`_권역별REF`, `_지점별REF` 등)는 VLOOKUP 데이터 소스입니다. 숨김 해제하여 원시 데이터를 확인할 수 있지만, 직접 편집하지 마세요.

## 2. solar_multi.py 출력

**파일명:** `solar_analysis_{올해}_{종료일}.xlsx`

### 시트 구성 (7시트)

| # | 시트명 | 내용 |
|---|--------|------|
| 1 | 설정 | 조회 조건 (올해·평년·기간) |
| 2 | 권역별 | 권역 선택 → 5개 지표 × 올해/작년/평년/차이 |
| 3 | 지점별 | 지점 선택 → 동일 구성 |
| 4 | 기간별(월별) | 권역=열, 올해/작년/평년/차이=행, 월별 블록 |
| 5 | 년도별 | 권역 × 연도 매트릭스 |
| 6 | 원데이터 | 지점별 일별 관측값 전체 |

### 일사·일조 지표

| 지표 | 단위 | 월별 집계 | 해석 |
|------|------|----------|------|
| 일 평균 적산일사 | MJ/m² | 일별 일사량의 평균 | 높을수록 일조 풍부 |
| 적산일사 | MJ/m² | 일별 일사량의 합 | 월/기간 총 일사 에너지 |
| 일 평균 일조시간 | hr | 일별 일조의 평균 | 높을수록 맑은 날 많음 |
| 적산일조시간 | hr | 일별 일조의 합 | 월/기간 총 일조 |
| 일조율 | % | 일별 일조율의 평균 | 100%에 가까울수록 쾌청 |

## 3. temp_multi.py 출력

**파일명:** `temp_analysis_{올해}_{작물}_{종료일}.xlsx`

### 시트 구성 (9시트)

| # | 시트명 | 내용 |
|---|--------|------|
| 1 | 설정 | 조회 조건 + Tbase·Tupper·계산방법·작물 |
| 2 | 권역별 | 권역 선택 → 6개 지표 × 올해/작년/평년/차이 |
| 3 | 지점별 | 지점 선택 → 동일 6지표 |
| 4 | 기간별(월별) | 권역=열, 월별 블록, 6개 지표 |
| 5 | 년도별 | 권역 × 연도 슬라이딩 윈도우, 6개 지표 |
| 6 | 적산온도 도달(권역별) | 도달일자 + 평년 + 차이 (VLOOKUP 동적) |
| 7 | 적산온도 도달(지점별) | 66개 지점별 도달일자 |
| 8 | 원데이터 | 일별 avgTa·maxTa·minTa·GDD |

### 온도 6개 지표 (전 시트 공통 순서)

| # | 지표 | 단위 | 월별 집계 | 해석 |
|---|------|------|----------|------|
| 1 | **평균기온** | ℃ | 일평균의 평균 | 해당 기간의 대표 기온 |
| 2 | **최고기온** | ℃ | 일최고의 **최댓값** | 해당 기간의 극값 |
| 3 | **최저기온** | ℃ | 일최저의 **최솟값** | 해당 기간의 극값 |
| 4 | **최고기온 평균** | ℃ | 일최고의 평균 | 일 최고기온의 일반적 수준 |
| 5 | **최저기온 평균** | ℃ | 일최저의 평균 | 일 최저기온의 일반적 수준 |
| 6 | **적산온도** | ℃·일 | 일 GDD의 합 | 작물 생육 열량 축적 |

> **최고기온 vs 최고기온 평균:** "최고기온"은 그 달에서 **가장 더웠던 날**의 온도이고, "최고기온 평균"은 매일의 최고기온을 **평균 낸 값**입니다. 7월 최고기온이 35℃이면 7월 중 하루라도 35℃에 도달했다는 뜻이고, 최고기온 평균이 30℃이면 7월 전체의 낮 기온이 대체로 30℃ 수준이었다는 뜻입니다.

### 설정 시트 — temp 전용 항목

| 셀 | 항목 | 설명 |
|----|------|------|
| B11 | 기준온도 Tbase | GDD 계산의 기준온도. `--crop` 옵션 사용 시 자동 설정 |
| B12 | 상한온도 Tupper | AquaCrop 방법 사용 시 적용 |
| B13 | 계산 방법 | `(Tmax+Tmin)/2` (기본), `avgTa`, `AquaCrop` |
| B14 | 작물 | 선택한 작물 ID 또는 "(사용자 지정)" |

### 년도별 시트 — 슬라이딩 윈도우

올해(B4)를 바꾸면 표시 범위가 자동으로 이동합니다.

| 올해 설정 | 표시 범위 | 평년 |
|----------|----------|------|
| 2026 | 2016~2026 (11년) | 2016~2025 평균 |
| 2024 | 2014~2024 (11년) | 2014~2023 평균 |
| 2030 | 2020~2030 (11년) | 2020~2029 평균 |

## 4. 적산온도 도달일자 해석

### 4.1 시트 구조

각 권역(또는 지점)마다 5행 블록:

| 행 | 예시 (500℃) | 의미 |
|----|-------------|------|
| 올해(2026) | `5-20` | 2026년에 500℃ 도달한 날짜 = 5월 20일 |
| 작년(2025) | `5-28` | 2025년 도달일 |
| 평년(2016~2025) | `5-25` | 과거 10년 평균 도달일 |
| 차이(올해-작년) | `−8` | 작년보다 8일 빨리 도달 |
| 차이(올해-평년) | `−5` | 평년보다 5일 빨리 도달 |

### 4.2 차이 행 해석

| 값 | 의미 |
|----|------|
| **음수 (−)** | 올해가 더 **빨리** 도달 → 올해가 더 따뜻함 |
| **양수 (+)** | 올해가 더 **늦게** 도달 → 올해가 더 서늘함 |
| `−` (대시) | 한쪽 또는 양쪽 데이터 없음 (미도달 또는 데이터 부족) |

### 4.3 임계값별 농업적 의미

아래는 일반적 참고용이며, 실제 생육 단계는 작물·품종·지역에 따라 다릅니다.

| 임계값 | 온대 과수 일반 | 활용 예 |
|--------|-------------|--------|
| 500℃ | 초기 생육 활발 | 1차 엽면시비 시기 참고 |
| 1,000℃ | 개화 전후 | 수분 관리 강화 시점 |
| 1,500℃ | 착과·비대기 | 적과·봉지씌우기 시기 |
| 2,000℃ | 성숙기 진입 | 과실 품질 관리 시작 |
| 2,500℃ | 수확기 | 수확 적기 판단 |
| 3,000℃+ | 만생종 수확 | 만생종 품종에 해당 |

### 4.4 Tbase(기준온도)에 따른 차이

같은 지역이라도 작물(Tbase)에 따라 적산온도 도달 속도가 달라집니다.

| 작물 | Tbase | 500℃ 도달 예상 (전국 평균) |
|------|-------|-----------------------|
| 사과 | 4℃ | 3월 중순 (빠름) |
| 포도 | 10℃ | 5월 하순 (중간) |
| 감귤 | 13℃ | 6월 중순 (느림) |

`--crop apple`로 실행하면 Tbase=4℃가 자동 적용되므로, 도달일자가 `--crop grape`(Tbase=10℃)보다 훨씬 빠릅니다. **다른 작물의 결과를 비교할 때는 반드시 Tbase가 같은지 확인하세요.**

### 4.5 "평년" 도달일이 비어 있는 경우

평년 도달일이 `−`로 표시되는 경우:

- **데이터 시작 연도 문제:** 평년 기간(예: 2016~2025) 중 초기 연도에 데이터가 부족
- **높은 임계값:** 해당 권역/지점에서 그 임계값에 도달하지 못하는 해가 있음 (서늘한 지역 + 높은 Tbase)
- **올해 설정 문제:** 올해를 2017로 설정하면 평년=2007~2016인데, 데이터가 2016부터여서 1년분만 있음

### 4.6 동적 갱신

올해(설정 B4) 셀을 바꾸면 올해·작년·평년·차이 5행이 모두 자동 갱신됩니다. 과거(2024) → 미래(2028)까지 자유롭게 탐색할 수 있습니다 (단, 데이터가 수집된 범위 내에서).

## 5. 자주 묻는 질문

### Q. 올해를 2030으로 바꿨는데 데이터가 비어 있어요

데이터가 2026년까지만 수집되었기 때문입니다. 2027년 이후 데이터는 아직 존재하지 않으므로 올해·작년 행이 빈칸이 됩니다. 평년 행은 평년 기간(2020~2029)에 해당하는 연도의 데이터가 있으면 표시됩니다.

### Q. 권역별 값이 기상청 홈페이지와 달라요

의도된 차이입니다. 본 시스템은 ASOS 지점 단순 평균을 사용하고, 기상청은 대표 지점 방식을 사용합니다. 기상청 값이 필요하면 "지점별" 시트에서 해당 지점을 직접 조회하세요. 자세한 설명은 [WEATHER_THEORY.md 6장](WEATHER_THEORY.md#6-다지점-집계-방법론)을 참조하세요.

### Q. "최고기온"과 "최고기온 평균"은 뭐가 다른가요

"최고기온"은 해당 기간(월) 중 **가장 높은 날의 최고기온**(극값)이고, "최고기온 평균"은 매일의 최고기온을 **평균 낸 값**입니다. 전자는 폭염 발생 여부 판단에, 후자는 일반적 낮 기온 수준 파악에 유용합니다.

### Q. 적산온도를 avgTa 방법으로 바꿀 수 있나요

실행 시 `--method avg` 옵션을 추가하면 됩니다. 단, avgTa 방법은 (Tmax+Tmin)/2 방법보다 3~4% 낮은 결과를 줍니다. 작물별 기준온도(crops_gdd.csv)는 (Tmax+Tmin)/2 방법을 전제로 산출된 것이므로, 방법을 바꾸면 기준온도와의 일관성이 깨질 수 있습니다.

### Q. 원데이터 시트가 너무 커요

66개 지점 × 약 10년 × 365일 ≈ 약 24만 행이므로 파일이 큽니다(약 20~30MB). 특정 권역만 분석하려면 `--region 강원영서` 옵션으로 대상을 줄이세요.
